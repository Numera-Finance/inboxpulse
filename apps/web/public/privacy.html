InboxPulse asks for broad access to your Gmail. Here is what it uses.

InboxPulse is an internal Gmail side panel built here. It shows which clients are unhappy and waiting, and lets you mark threads to come back to. Installing it puts a Google consent screen in front of you whose wording is much wider than anything the add-on does — so this sets out that sentence, every Gmail call in the code, which build is running, and who can change it.

01The sentence you will see

Google words its consent screens by scope family, not by what an application does with them. Approving InboxPulse shows this:

Google consent screen Read, compose, and send emails from your Gmail account.

That is the wording for gmail.modify. It is required for one reason: attaching a label to a thread is the users.threads.modify API, and no narrower scope grants it. gmail.labels creates and renames label definitions but cannot put one on a message. There is no third option, and nothing in the product can change that sentence.

05Why it cannot quietly do more

Each promise below is a property of the code, not a policy. The file is named so it can be checked rather than believed.

Nothing is read until you say so

Reading is off by default, per person. Without consent the thread text is never assembled and no model call is made.

apps/addon/src/services/consent.ts

No message text is stored anywhere

The summary cache is in process memory and there is no code path that writes it anywhere else. It could once persist to disk behind an unset environment variable; that branch has been deleted rather than switched off, because an unset variable is a promise about configuration and anyone with deploy access can change it without telling you. The add-on has no database client at all.

apps/addon/src/services/analysis-cache.ts

Only you can see your panel

Every render is scoped to the account Google authenticated on that request. Logs record a salted, namespaced one-way hash instead of an address, so an engineer reading production logs cannot tell whose panel it was.

apps/addon/src/services/api-client.ts · pseudo() — see section 07

Every write is reversible in one press

All labels live under a single ⚡/ namespace. Deleting a label removes it from every thread that carried it, so “Clear all my marks” is one operation and cannot miss one.

apps/addon/src/gmail/labels.ts · clearAllOfLabel()

The label expiry uses your token, not a stored one

Marks clear after 30 minutes — but nothing runs on a schedule to do it. The sweep happens when you next open the panel, using the token Google mints for that request, and there is no background job, no service account and no stored credential that can touch your mailbox while you are away. If you never open the panel again, nothing ever calls your mailbox again.

apps/addon/src/index.ts · sweepExpired()

06Where the firm-wide numbers come from

The client figures in the panel — who is waiting, who is slow — are not derived from your mailbox. They come from a shared mailbox the firm already routes client correspondence through and has been analyzing for months. That predates this add-on and is unaffected by whether you install it.

Installing or refusing this add-on changes nothing about that mailbox — the analysis runs either way.

Each of the three inputs is doing a specific job, and dropping any one of them would break the guarantee:

Ingredient
What it prevents
The address is hashed
A one-way function. The log holds no address to read.
A secret salt is mixed in
Without it, a plain hash of a work email is not anonymous — a firm has a finite staff list, and anyone could hash every name on it and match. The salt lives in Secret Manager. That is not a separate grant from the logs — a project Owner reads both, so the people who hold Owner are exactly the people who could reverse this. The salt defends against a curious engineer with log access, not against the trust boundary.
A namespace is mixed in
The same address hashed as a viewer and as a customer domain produces different digests, so the two cannot be cross-referenced to link you to an account.

Two qualifications. The per-thread log line records only the classification, whether a summary was produced, and cache counters — your address is not in it at all, hashed or otherwise. And when a model call fails, we log only the provider's numeric error code and status. We discard the error body. We used to truncate it and write it out, and removed that because a content filter can quote the input that tripped it.

If the salt is ever missing, the function returns the literal string redacted rather than falling back to an unsalted hash. A digest that looks anonymous and is not would be worse than plainly omitting the value.

08The risk that is actually yours

Your mail already lives on Google’s servers and Gemini is already in your Gmail toolbar. That is not the same as this: your Workspace agreement with Google is not the same legal object as thread text posted to a Gemini endpoint under an API key held by a project four colleagues own. Google’s Gemini API writes the summary. We call it from our own Google Cloud project at generativelanguage.googleapis.com, model gemini-3.1-flash-lite, using an API key we keep in Secret Manager. This is the Gemini API, not Vertex AI. A Vertex deployment inside our own project would carry contractual zero-retention and no-training terms. The Gemini API's paid-tier terms apply instead.

The exposure this add-on genuinely adds is different, and it is not technical. Granting the permission gives a token to software we deploy. Everything in section 02 describes the code running today; anyone who can deploy new code to that project could ship a version that uses the same token differently, and you would not see a second consent screen.

Four people hold Owner on the Google Cloud project that runs this add-on. Any of them can deploy code that uses your token differently.

You can revoke it. Google Account → Data & privacy → Third-party apps kills the token immediately, without asking us. The add-on stops working the moment you do.

You can see the labels. Every mark the add-on puts on your mail shows up in your own Gmail sidebar under ⚡/, not in a log you cannot read.

09What you control

  • Turn reading off — one button in the panel. Takes effect immediately; nothing further is read.
  • Clear all marks — removes every label the add-on has ever applied.
  • Revoke the permission — Google Account → Data & privacy → Third-party apps. Kills the token; the panel stops working entirely.
  • Uninstall — removes the add-on from Gmail.
